# Astribot 双臂光绘参考图生成规范 v2：固定底盘、躯干协同与双臂同步

你是图案生成 agent。你的任务是生成适用于指定机械臂绘制平面的参考图与**有序轨迹**，不是直接控制机器人。必须读取本规范及同目录 `inputs/` 文件；不能凭预览图片猜测可达区域。

## 1. 固定输入与坐标

- `inputs/mask-left.png` 和 `mask-right.png`：570×471 单通道二值掩膜，255 是该臂分配的设计区域，0 禁止绘制。按机器人本体命名：**左臂在画面右侧（蓝色），右臂在画面左侧（橙色）**。
- `inputs/calibration.json`：固定标定。`inputs/cropped-regions.png` 只是设计参考，不可混入输出图。`inputs/blank-transparent.png` 是空白尺寸模板。
- 输出画布必须为 **570×471 像素**，不得自动裁剪、缩放、旋转、镜像或补边；横向 u 向右，纵向 v 向下。使用连续图像边缘坐标，像素中心为 `(整数+0.5, 整数+0.5)`；轨迹浮点坐标无需取整。
- 原始 960×720 图中裁剪框为 `[195,0,765,471)`，每像素 `0.003328153882611492 m`。裁剪只是平移图像坐标，实际约 1.897×1.568 m。
- 像素到世界坐标：`x=(u-285)*0.003328153882611492`，`y=-0.20`，`z=0.95-(v-360)*0.003328153882611492`，单位米。此规则对应固定底盘、80 mm 光棒发光端。掩膜仍是既有中性躯干姿态下的设计子集；执行允许真实躯干关节与双臂协同，但不得因此声称已算出扩大后的全部工作空间。
- 这是固定平面上、原相机视野内的采样可达区域；顶部仍有视野截断。矩形四角不一定可画。**不是完整三维工作空间，也不是无碰撞区域。**

## 2. 曲线要求（硬约束）

每个设计含左右臂各一条曲线，分别是一笔完成：
1. 每臂恰好一个有序点列，不得用多个子路径、断笔或隐藏连接线拼接；另一只手不可接续同一笔。双臂同步绘制；JSON 中左右臂数组顺序只是存储顺序，不是先后执行顺序。两条曲线分别参数化，再由共同时间进度驱动。
2. 全路径，包括相邻点之间的线段，必须位于对应掩膜内。对二值掩膜补一圈零后计算欧氏距离变换，中心线到无效区域的距离至少 **15 像素（约 50 mm）**。这是保守的设计缓冲，不是物理碰撞距离。
3. 相邻点欧氏距离必须大于 `1e-6` 且不超过 **1.0 像素**；约按弧长均匀采样。每臂 50–5000 点，长度 0.30–4.0 m。禁止 NaN/Inf 或重复停留点。
4. 采用解析平滑曲线、圆角曲线或经检查的样条。相邻线段转角不超过 **12°**，离散曲率估计 `转角 / 两段平均长度` 不超过 **0.10 rad/像素**（约束近似最小曲率半径 10 像素）。不要尖锐心尖、折线羽毛、锯齿或孤立细节。此数值只是图形预筛，不证明关节可执行。
5. v2 **禁止自交、重走线段**。闭合曲线允许首末点相同，但只允许这一重复端点，且闭合接缝须满足相同转角/曲率限制。开放曲线的起止速度由后端规划为零，不必把端点复制多次。
6. 末端朝向不指定；不要要求固定笔姿或面法向。不要输出关节角，不要自行作硬件速度/力限制承诺。时间规划、连续逆解和碰撞检查由后端完成。

建议先做简单、有辨识度的平滑图案：双波浪、圆滑水滴/叶片、无尖角的翅膀轮廓等。不要把“好看”优先于约束；可先在较小范围内设计。不同组应有明显不同的几何结构，不要只换颜色。

## 3. 每组输出文件

在 `generated/<英文小写名称>/` 输出以下文件：
- `paths.json`：下述严格结构，是几何事实来源。
- `drawing.png`：570×471，**RGBA，透明背景**，仅包含两条白色线 `(255,255,255)`；描边宽 **3.0 像素**，圆端/圆连接，4×超采样抗锯齿。透明像素 RGB 值不作要求。无标签、箭头、点标记、坐标轴、阴影、渐变、人物、机器人、彩色区域或签名。两臂可共用一张图，不允许凭图像重建顺序。
- `preview.png`：独立可视化，可含掩膜底色、名称、起止标记和绘制顺序。不可作为控制输入。
- `generate.py`：可复现本组图形的生成代码；所有随机数必须有固定种子。推荐调用同目录外的 `drawing_contract.py` 标准渲染器，避免坐标偏半像素。
- `validation.json`：用提供的 `validate_drawing.py` 获得，不手写“通过”。

`paths.json` 示例结构（示例点是假数据，不可直接执行）：
```json
{
  "schema_version": "astribot-drawing-v2",
  "name": "rounded_leaves",
  "canvas": {
    "width": 570,
    "height": 471,
    "coordinate_system": "continuous_pixel_edges",
    "meters_per_pixel": 0.003328153882611492,
    "crop_offset_original": [195, 0]
  },
  "execution": {
    "mode": "synchronized",
    "simultaneous": true,
    "progress": "shared_normalized_arc_length",
    "time_scaling": "quintic_zero_endpoint_velocity_acceleration",
    "draw_start_finish": "shared",
    "transfer_planning": "coupled_collision_checked",
    "tool_orientation": "unconstrained",
    "base": "fixed",
    "torso": "shared_coupled_actual_dofs"
  },
  "strokes": [
    {"arm": "left", "closed": false, "points": [[400.5,200.5],[401.0,200.7]]},
    {"arm": "right", "closed": false, "points": [[150.5,200.5],[150.0,200.7]]}
  ]
}
```
每组按该结构输出；每只手的路径方向只由其 points 数组决定，不能按像素排序；strokes 数组顺序不构成双臂时序。无需世界坐标字段，避免两套坐标不一致。可另外保存 SVG，但 SVG 不能替代 JSON；图片生成模型产生的栅格图只能当创意草图，不得声称符合此规范，除非重建成有序路径并通过所有检查。

## 4. 标准流程与停止条件

1. 读掩膜与标定，设计一条/臂平滑曲线。
2. 按弧长密采样，构建 JSON，调用标准渲染器生成 PNG。
3. 运行 `python3 validate_drawing.py generated/<名称>`；修正直至 `design_pass=true`。不得缩放掩膜或降低阈值来通过。
4. 提交所有产物，并明确**只是格式/几何设计检查通过**，`robot_execution_status` 必须为 `not_tested`。
5. 后端另做共享躯干与双臂的耦合连续逆解、全身碰撞检测、稠密插值、关节限位/奇异性、同步时间规划和实际动力学执行。任何失败都报告原图、失败位置和原因，不得悄悄改图、跳点或瞬移并宣称成功。必要时重新生成并重新标版本。
6. 只有执行后端实测才可报告具体轨迹的执行结果；未验证的任意图案、双臂同时执行、完整碰撞安全或实机性能均不可从掩膜推断。

## 5. 同步全身执行契约（底盘固定）

当前不考虑人体。机器人底盘保持固定，**只允许模型真实存在且可控制的躯干自由度**，不凭想象增加竖直升降轴。躯干是否通过升降、俯仰或其他关节改变高度，由后端核实模型并记录实际关节名、类型、限位与执行器。两臂必须共享同一条躯干轨迹，禁止分别求出互不一致的躯干姿态再拼接。

当前模型已核实包含 `astribot_torso_joint_1` 至 `astribot_torso_joint_4` 四个转动关节，不是直接竖直升降的移动副。依次位置限位为 `[0,1.5]`、`[-2.35,0]`、`[0,2.4]`、`[-1.58,1.58]` rad。执行报告须再对应实际加载模型核对。可用预设共享躯干姿态曲线加双臂补偿逆解，也可用联合优化；前者须称为“姿态引导的全上身协同”，不得冒充通用全身最优控制器。

- 每臂路径用各自累计弧长归一化到 s∈[0,1]，共用同一单调进度 s(t)。路径长度不同时末端线速度可以不同，不能为了同速删点或改形状。
- 绘制阶段同一时刻开始、结束，默认使用端点速度及加速度为零的五次时间进度。后端根据躯干与两臂最严的已知运动约束确定共同持续时间，不由图案 agent 编造硬件速度额定值。
- 接近、绘制、收回、停留均纳入同一全身配置与碰撞检查。接近/收回可采用耦合规划的分阶段轨迹，但须明确阶段时间、各部件是否运动及保持姿态，不能把未检查的瞬时跳转藏在阶段之间。
- 全身规划变量包括两臂与共享躯干的实际关节；底盘位置不允许用作绕过碰撞或可达性约束的自由变量。目标绘制平面和原始路径固定在标定坐标中，躯干运动不能偷偷移动画布。
- 规划需检查双臂之间、同臂非相邻连杆、机械臂与躯干/头部/底座、夹爪与光棒，以及适用的非人体环境。自然相邻关节的合理排除必须逐对记录；不能用排除所有同一机械臂或同一机器人来获得“无碰撞”。
- 不得仅按端点或单臂轨迹分别验收。检查至少覆盖完整计划与真实执行记录，并说明时间/配置空间采样间隔和插值细化。离散采样未检出碰撞不等于数学意义上的连续碰撞证明。

`execution-contract.json` 是当前准确元数据；必须原样使用。尚未找到可行共享躯干姿态或同步无碰撞方案时，报告失败阶段、对象和原因；不能悄悄变成逐臂执行、冻结必要的躯干变量、改图或瞬移并称为通过。

## 6. 后端分项报告与接受条件

设计 agent 的 `validation.json` 只报告静态格式及平面几何，不做运动或碰撞认证。执行后端另输出报告：

1. `design_status`：格式、掩膜、路径顺序、JSON/PNG 一致性。
2. `coupled_ik_status`：真实关节列表、共享躯干求解、连续性、目标误差、限位余量、奇异性诊断。
3. `synchronization_status`：两手实际绘制起止时间、共享进度定义、共同持续时间、底盘固定误差、躯干运动范围。
4. `robot_collision_status`：碰撞模型版本/来源/哈希，启用几何和检查对清单，排除对及理由，夹爪与光棒覆盖，近似或欠覆盖部位；计划及实际各阶段的最小有符号距离、对象对、时刻、检测分辨率、所选工程缓冲及理由。
5. `tracking_status`：两手与躯干实际跟踪误差、状态有限性、仿真警告、关节速度/加速度及额定限制来源，实际积分方法。
6. `human_interaction_status=out_of_scope`；`hardware_safety_status=not_validated`，除非另有实机验证证据。

负距离表示所用模型预测重叠；近似包围体相交不必然等于精确实物接触，但必须拒绝该近似模型下的通过。欠覆盖的包围体即使分离也不能保证实物分离。碰撞模型不完整时明确未验证，禁止把 `ncon=0` 或低跟踪误差当安全证明。

各检查通过只允许说“在列明的模型、检查对、缓冲与检测分辨率下，当前同步轨迹通过”。必须同时保留模型近似、自碰撞覆盖、离散采样以及实机限制。若碰撞导致重新选姿态/规划接近路径，保留原失败记录和新版本；图案变动需重新生成与验证。

## 7. 当前实现的适配说明

本次 v2 三组图案通过 `check_backend_inputs.py` 映射到预先求解的 `seed-plans.npz`；原实测使用该 NPZ 的世界坐标及关节初值；交付的复现 `sync.py` 已读取 v2 JSON、检查同步标记及其世界坐标与 NPZ 的一致性，再使用同一关节初值。完整静态契约检查与 NPZ 一致性检查都须在执行前完成。该输入适配不等于新做了一次动力学复验。新的图案需要重新构建初始计划，不得把旧 NPZ 与新 PNG 混用。

当前碰撞实现采用 MuJoCo 凸包表示和明确的对象对排除，不是精确三角网格连续碰撞检测。计划工程门限、实际采样判据、接触 margin 必须分开报告；不能用“计划 2 mm”暗示所有实际样本都满足同一余量，也不能用有限采样通过承诺所有采样间时刻无碰撞。具体模型版本和实测结果见执行报告。

当前后端的躯干姿态参数表针对三组既有图案，尚不是任意新 JSON 的通用自动全身规划服务。新增图案必须重新构建逆解种子、选择躯干参数并做全过程检查，不得沿用旧图的“通过”。
