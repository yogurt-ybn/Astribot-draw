# 同步双臂与共享躯干生成规范 v2

本目录是 v1 的新版本，不覆盖旧工程。把整个目录交给有 Python 执行能力的 agent，再发送 AGENT_PROMPT.zh-CN.md。主要规范为 AGENT_DRAWING_SPEC.md，机器可检查元数据为 execution-contract.json。

当前底盘固定，不考虑人体；后端允许真实躯干关节与双臂协同。两手共享归一化路径进度与时间，不能分别选择相互冲突的躯干姿态。完整机器人碰撞验收由后端决定，静态验证不代替它。

`generated/` 三组仍是原有波浪、圆滑叶片、双旋涡。迁移只改变 schema 和 execution 元数据，原始坐标及透明 PNG 不变；source-v1-paths.json 保留原数据。generate.py 可重做迁移和渲染。migration-report.json 记录逐组一致性与静态检查。

安装 requirements.txt 后运行：

```bash
python3 test_validator.py
python3 validate_drawing.py generated/tidal_waves
```

需要全部 masks、calibration 和标准渲染器，不能只发 MD 或截图。现有掩膜仍是中性躯干下的可达设计子集，未重新计算全身扩展工作空间。底盘、安装、光棒尺寸、平面标定变动需要重新验证。

本目录没有宣称同步运动或无碰撞已经通过；执行结果属于独立后端报告。要保留碰撞模型覆盖、抽样分辨率及实机限制。

当前躯干是 astribot_torso_joint_1..4 四个 hinge。改变身体高度来自关节组合运动，不是额外虚拟竖直轴。后端若使用预设躯干曲线及双臂补偿，应如实称为姿态引导的全上身协同，而非通用全身优化控制。

## 本次后端对接与模型边界

已有实测运行读取 `inputs/<图案名>/seed-plans.npz` 中的世界坐标与关节初值。交付的复现入口现已加上 v2 JSON 读取，检查 simultaneous=true，并检查 JSON 转换后的世界坐标与种子 NPZ 一致；该接口适配没有冒充重新运行整段动力学。已用 `check_backend_inputs.py` 独立核对：三组共六条 NPZ 世界坐标与本目录 v2 JSON 经标定映射所得数组完全相同，最大差为 0；图案形状没有改动。完整 JSON 同步契约由此检查入口验证，后端同步模式由其实现固定执行；它不是任意 JSON 配置都可直接执行的通用接口。可运行：

```bash
python3 check_backend_inputs.py /path/to/astribot-sync-collision
```

该检查只证明输入一致，不替代运动执行。新的图案还需要先求解并生成适用的 seed-plans.npz、选择共享躯干姿态参数并重新规划检查。当前 sync.py 的姿态参数表针对这三组已验证名称；新名称没有默认已验证参数，不能简单更换图片文件就运行。

本次执行使用真实四关节躯干的姿态引导倾身曲线，两臂补偿世界坐标目标；不是通用全身最优控制器。双臂共用归一化弧长进度和五次时间缩放，接近、绘制与收回均同步实际积分。身体运动通过 hinge 组合产生，底盘固定。

碰撞模型将原始连杆网格作为 MuJoCo 凸包，结合地面、夹爪垫及 7 mm 半径光棒胶囊；使用 MuJoCo 3.4 的 libccd 距离算法，关闭该版本 native convex distance。当前显式检查 1,071 对几何，配套 collision_model_report.json 逐对列出检查与排除。凸包会填平凹部；机械相邻/固定装配及其他列明排除对不在检测集合内，不能称为精确三角网格对所有实体的完备碰撞认证。

计划阶段距离门限 2 mm，接触 margin 为 1 mm；实际每 10 ms 检查列明对象对，代码以非负距离作为实际无重叠判据，并报告测得最小值。2 mm 是此次规划工程门限，不是适用于实机的安全余量。最小值附近额外细化若有，具体范围和分辨率以执行报告为准；任何有限采样都不构成连续时间无碰撞证明。

当前三组执行结果应由最终执行报告引用，不能把原 v1 单臂结果继承为同步通过。可报告在该凸包模型、检查对集合及抽样分辨率下的实测结果，但必须保留碰撞覆盖、排除对、采样和实机限制。
