# Publication provenance

The frozen v3 simulations and their measurements predate this publication. Original freeze, source hashes and full-rate trajectory hashes remain evidence of that run, not a claim that portable source bytes are identical. `publication-diffs.json` maps original delivery hashes to publication hashes.

Packaging changes: t1_model.py uses repository-relative descriptions/ or ASTRIBOT_T1_ASSETS rather than a private machine fallback. run_benchmark.py records an optional locally generated asset-manifest hash and the pinned upstream commit, allowing execution with an externally supplied asset checkout. No IK, geometry, timing, candidate or collision algorithms were changed. JSON report input paths and renderer run path were normalized to relative paths; their original hashes in visual metadata refer to the original reports. Other numerical evidence is unchanged. Setup/renderer documentation is portable. The original DELIVERY_SHA256 manifest is replaced by PUBLICATION_SHA256 for this public package.

No new dynamics rerun was performed for these packaging changes. Unit/static/hash/geometry checks are recorded separately. Original upstream assets, generated asset_manifest.json, and large full-rate trajectories are not published. Download assets locally and rerun to reproduce full-rate trajectories. This finite search can reject reachable drawings; sampled collisions and simulation are not a real-hardware safety proof.

Publication excludes three optional model/environment inventory files (v1 environment-freeze, v2 inherited-model-environment-evidence, v3 model-freeze): they contain extensive upstream model asset path/hash inventories and were not approved for public upload. This is an explicit evidence-package omission, not a new verification or a replacement model freeze. The original tested upstream commit, source/input/config freeze and result evidence remain documented. No asset-inventory content is republished through another file.

The owner requested no MP4 in this publication. All three newly generated MP4 files are omitted; existing historical S1/T1 repository videos are unchanged. Renderer metadata still describes the original local render process, not the set of publicly shipped media.

## SDK simulation integration extension (2026-10-24)

The optional `initial_qpos` argument to `ik_candidate` accepts a checked measured full-model pose for the SDK adapter. Omitting it preserves the canonical-start benchmark behavior above. This extension and the SDK execution layer are separate from the historical frozen v3 simulations. A fresh official-simulator SDK run for ginkgo is recorded in `../robot_sdk/examples/svg-ginkgo-verification.json`; it uses the simulator's installed model assets, rechecks kinematics and sampled geometry, and reports FK from actual received joint feedback. No hardware execution or model assets are published. The publication hash list includes the extended source and this provenance note; historical freeze hashes are retained unchanged.

The SDK adapter now requests `schedule(..., return_home=False)`, ending at the drawing endpoint with zero velocity. The default `return_home=True` preserves the historical standalone benchmark. Stop-at-end execution and stage timing are separately verified by the SDK adapter; this does not replace the frozen v3 evidence.

An optional `timing="progress_bound"` schedule uses interval-wise conservative bounds on the product of joint-spline derivatives and smooth progress speed, while retaining the 0.2 rad/s joint and 0.05 m/s tip ceilings. The default `timing="legacy"` is unchanged. The SDK validates geometry once on all final 125 Hz commands instead of traversing both native 200 Hz and resampled trajectories. The measured-start planning-margin check tolerates 1e-9 rad of roundoff without clipping the measured state or changing physical limits. New SDK verification is independent of frozen historical results.

Optional `joint_speed` and `tip_speed` schedule arguments expose absolute planning velocity ceilings. Their standalone defaults remain 0.2 rad/s and 0.05 m/s, preserving historical benchmarks. The simulation SDK passes explicitly configured ceilings, optionally slows to a requested total duration only when it fits those ceilings, and validates final joint and Jacobian tool-tip command velocities. The SDK also records bounded simulation command preview separately from the nominal trajectory; original tracking thresholds remain unchanged.

The SDK now defaults to `timing="feedrate"`: path-length cruise timing with interval joint-derivative/curvature bounds, forward/backward speed propagation, zero endpoint velocities and smooth entry. Total motion duration follows path length and constraints, not a fixed global time. The SDK defaults are a 1 rad/s joint ceiling and 0.2 m/s virtual-tip cruise/ceiling (with 5% interpolation/tracking headroom); standalone legacy defaults remain unchanged.

The feedrate verification separately records planned and received-feedback FK velocities. The nominal 0.2 m/s planning ceiling is not a physical servo-speed guarantee: the tested simulator still exhibits a transient feedback peak near 0.223 m/s. The unchanged 2 mm position tracking gate passed; no measured-speed gate is claimed.

## Uniform SDK target sampling and simulation gripper option (2026-10-24)

The SDK now requests `shared_targets(..., sampling="uniform")`. The common normalized arc-progress grid uses at most 2.5 mm of longest-arm arc per interval and is uniformly refined until its same-progress deviation from the source parsed polylines is bounded by 0.1 mm. Source vertices bound this difference between the union of both grids. This sampling error is included in the final 1 mm command-shape budget. Original standalone vertex sampling, IK posture preferences, speed ceilings and feedrate acceleration budgets are unchanged.

An explicit `--skip-gripper-checks` option is restricted to official simulation ROS drawing. It skips gripper feedback checks and uses fixed preset finger geometry, without commanding the grippers. It does not validate physical grasping or actual finger articulation. Other state, command and runtime geometry checks remain enabled.

Fresh five-design SDK simulation regression: all five motions completed; three passed the unchanged 2 mm audit, while S curves and wings reached 2.042 and 2.543 mm peak errors. The asymmetric spiral completed in 11.666 s versus 71.121 s before resampling, with 1.842 mm maximum FK position error. A plan-only replay from the exact same previously recorded start reduced its validated complete plan from 71.110 to 11.960 s. Actual serial runs replan from differing current poses and are not a controlled same-start comparison. The official container passed 44 SDK and 34 planner tests. These new results are separate from the frozen historical benchmarks; compact evidence and portable SVG inputs are in `../robot_sdk/examples/generalization/`.

The deployment policy subsequently changed measured drawing position accuracy to a report-only quality metric. The 2 mm reference, per-arm maximum/RMS and warning status are still recorded, but exceeding it no longer rejects otherwise completed motion or returns a CLI error. Control, feedback, substantial joint tracking and collision checks are unchanged. Historical strict-audit records are retained as measured and are not rewritten under the new policy.
