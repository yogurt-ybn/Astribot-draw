# Astribot T1 双臂 SVG 生成规范 v1.1

## 任务和真实边界
生成供规划器读取的 **SVG 矢量中心线原稿**，不是位图描摹，也不是把 JSON 导出的预览冒充输入。一个 SVG 同时包含左右机械臂各一条连续路径。底盘固定，不考虑人体；双臂同步且共用可运动躯干。生成器只负责几何设计，不能自行宣称无碰撞、可执行或已完成仿真。

配套输入：`t1-canvas/calibration.json`、`mask-left.png`、`mask-right.png`。不得更改它们；模型为 Astribot T1，不是 S1。每个候选需要独立 SVG、从该 SVG 渲染的 PNG、验收报告。建议至少三组不同形状，包含一个展开翅膀候选，而非仅改色。

## 1. 唯一坐标系，不自动适配
- SVG 根节点固定 `width="616" height="560" viewBox="0 0 616 560"`，生成时使用无单位数字。解析器亦接受相同数值加 `px`，不接受其它单位。
- 连续像素边界坐标：u 向右、v 向下，像素中心是整数 + 0.5。路径须满足 `0 <= u < 616, 0 <= v < 560`。
- **left 指机器人左臂，在画面右侧；right 指机器人右臂，在画面左侧。** 不按观众左右重新命名。
- 世界坐标（米）：`x=-0.77+0.0025*u`，`y=-0.42`，`z=1.89-0.0025*v`。整幅画布物理尺寸 1.540 × 1.400 米。
- 不裁掉空白后重设 viewBox；不缩放、平移、旋转、镜像、居中适配，不偷偷简化、重排、补闭合线。设计不符合时修改原稿并记录，不让导入器“修复”。

## 2. 机械区域：必须检查真实遮罩
- `left` 路径完全处于 `mask-left.png` 白色区域；`right` 使用 `mask-right.png`。单通道值大于 127 表示候选允许区。
- 不能只检查起终点或控制点。使用所附 `svg_input.py` 的 `parse_svg` + `validate_masks` 检查整个细分折线及曲线误差包络；不要自行重写一个更宽松的检查替代它。
- 曲线可经过控制点凸包内部而非控制点本身，因此控制点在区域内不是充分验收。为减少拒绝，设计时留出可见余量，不贴遮罩边界。
- 遮罩是若干躯干姿态下的单臂可达采样并集，不代表任意双臂目标可以在同一躯干姿态同时到达，更不证明整段连续轨迹无碰撞。

## 3. 文件和 XML 的精确子集
生成 **UTF-8、不带 BOM、不带 XML 声明** 的 `.svg`。根元素使用 `xmlns="http://www.w3.org/2000/svg"`。

根节点可用普通属性仅 `width,height,viewBox,version`。本规范只使用前三项。根节点下面必须恰好两个**直接** `<path>` 子节点，分别 `id="left"` 和 `id="right"`。不能用 `<g>`、编辑器图层或嵌套 path；编辑器导出须先将图层展开到这两个直接 path。

path 可用属性仅 `id,data-arm,d,fill,stroke,stroke-width,stroke-linecap,stroke-linejoin`。解析器允许 `data-arm` 标注，但生成器统一只用 id，避免冲突。生成器必须显式 `fill="none"`（解析器省略时视为 none，浏览器默认填充不同，不能省略）。颜色使用普通十六进制色；线宽建议 `2`，端点/接头 `round`。这些是预览样式，机械臂跟踪中心线，不沿笔画边缘走、不填充区域。

禁止任何其它属性、非空 XML 文本、XML 注释、声明、DTD、实体声明、处理指令、脚本、CSS/style、transform、clipPath、SVG mask、filter、marker、opacity、hidden、image、text、use、链接、外部资源、嵌入位图。辅助遮罩只在生成/验证阶段读取，不能放进输入 SVG。SVG 内不得带标题文字、图例、起终点圆点或背景 rect。标注需放在独立报告/预览副本中，不污染输入文件。

## 4. 一笔画命令和路径顺序
- 解析器仅支持 `M L C Q Z` 及相应小写相对命令，支持重复参数组。**不支持 A/H/V/S/T**。生成器进一步收紧为显式大写绝对命令，每个参数组写一次命令，空格分隔数值，不使用指数表示，便于人工审查。
- 每条 path 恰好一个起始 `M`，后续只能 `L/C/Q`，可选最后一个 `Z`。不得有第二个 M、断笔子路径、分叉图、多个独立轮廓。Z 后不能继续命令。
- `M u v`；`L u v`；`Q c1u c1v u v`；`C c1u c1v c2u c2v u v`。坐标须有限，路径必须非零长度。
- 开放曲线合法，不自动闭合。若使用 Z，最后一点至起点的直线也是要执行的轨迹，必须满足同样区域规则。优先使用平滑 C/Q，避免尖角、原路瞬时折返、自交和零长度段。这些平滑性是设计目标，不是解析器已经证明的动力学条件。
- 源文件 d 的顺序就是运动顺序，起点就是 M。不要依赖 SVG 节点排列表示先左后右：两臂是同时执行。

## 5. 同步和几何保真
解析器将曲线自适应展开为折线，曲线到折线的误差界不超过 0.1 px（0.25 mm），最大折线段长 1 px。不改变源 SVG；移除零长度段时计数报告。

每臂分别按累计弧长归一化为 s ∈ [0,1]，共享同一个平滑时间进度，起终时刻一致。**相同 s 不代表相同顶点编号、相同参数 t、相同高度或相同速度**；长度不同的双臂平均末端速度也不同。所有细分顶点保留在共享进度网格。不是历史旧 JSON 的顶点索引同步规则。

不要在 SVG 中编码“同编号点同时到达”或独立左右臂时间表。躯干可动、双臂之间以及双臂与机器人身体的碰撞，必须交给后续联合规划和动态仿真验证；二维中心线不相交不能替代这些检测。

## 6. 最小语法示例
以下是完整语法示例，不是可执行性保证；提交候选仍须独立验证。

```xml
<svg xmlns="http://www.w3.org/2000/svg" width="616" height="560" viewBox="0 0 616 560">
  <path id="left" fill="none" stroke="#2563eb" stroke-width="2" stroke-linecap="round" stroke-linejoin="round" d="M 436 310 Q 442 314 436 318"/>
  <path id="right" fill="none" stroke="#f97316" stroke-width="2" stroke-linecap="round" stroke-linejoin="round" d="M 180 310 Q 174 314 180 318"/>
</svg>
```

不要将本例微小曲线直接充作三种新设计。

## 7. 提交物与验收
每组提交 `<name>.svg`、`<name>.png`、`<name>.report.json`。SVG 是唯一几何源。用所附 `validate_and_render.py` 完成静态验证和 PNG 渲染：

```bash
python validate_and_render.py output/wings.svg --out output
```

PNG 必须由同一个 SVG 经 CairoSVG 安全渲染（先通过严格解析，再以 unsafe=False 渲染），固定 616×560；不得拿其它点列/独立手画图冒充 SVG 渲染。须比对解析折线渲染与 SVG 渲染的可见曲线，并记录容差和差异；PNG 用透明背景，查看时可垫白色。人工检查可看独立标注拼图，但不改原 SVG。

报告至少包括：候选名、源文件 SHA256、静态/遮罩状态、每臂包围盒/世界米制长度/闭合与否/细分点数、曲线误差界、渲染比较方法与结果、修改记录、`mechanical_feasibility: "UNVALIDATED"`、`ik: "not_run"`、`full_plan: "not_run"`、`simulation: "not_run"`。失败写具体原因，不输出成功字样。报告或预览不得宣称 hardware-ready。

静态通过只表明格式、几何、采样遮罩通过。后续规划还需共享躯干连续 IK、进场/同步绘制/退场、关节与速度限制、全机器人碰撞检测；后续仿真还需实际跟踪误差和碰撞检查。有限采样检测不是连续扫掠体证明，当前不验证人体、底盘移动、接触绘画、末端朝向、加速度/jerk/力矩裕量、奇异性阈值和真机安全。生成器无权跳过这些阶段。

## 8. v1.1 强制几何平滑性门槛（不是机械认证）

v1 原先只将平滑作为偏好，因此初轮的尖角候选虽格式/遮罩通过，不能视为完整满足 v1.1。原稿和报告保存在 `history/v1/first-attempt/`，历史 PASS 仅代表当时的格式、遮罩与渲染检查。

新增 `smoothness.py` 是生成验收硬门槛，而不是修改后端 SVG 语法：
- 每个 L/Q/C 段接头的**有向切向夹角不得超过 5°**，闭合曲线还检查末段到首段。Z 产生非零闭合直线时，它也是独立段并检查两端接头。
- 每个段以 1025 个等参数采样点计算解析一阶、二阶导数，曲率 `abs(x' y'' - y' x'') / (x'^2+y'^2)^(3/2)` 不得超过 **0.1 /px**（等价局部半径至少 10 px，即 25 mm；仅就采样点而言）。
- 任何采样点一阶导数模长 <= 1e-9 都拒绝，避免不确定切向和退化尖点。C/Q 端点控制点不要与端点重合；零长度 L 也不允许通过此设计门槛。
- 这些阈值是保守的图形设计预筛选，不是由机器人速度/加速度/碰撞裕量标定的运动极限。有限采样曲率未证明采样点之间的上界；5° 允许误差也不是严格数学 C1 连续。通过不代表动态可执行。
- 失败必须回到**源 SVG**调整控制点或圆滑转接，并记录修改；禁止只在 PNG、解析器或渲染器里圆滑。所有原坐标标定与遮罩限制保持不变，不能放宽阈值为设计过检。

最新报告须有 `format_and_masks: PASS` 及 `smoothness.status: PASS`，总 `static: PASS` 才表示 v1.1 静态通过，机械阶段仍是 UNVALIDATED/not_run。
